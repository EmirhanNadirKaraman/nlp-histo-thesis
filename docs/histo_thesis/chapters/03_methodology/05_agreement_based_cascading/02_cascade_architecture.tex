\subsection{Cascade architecture}\label{subsec:abc-architecture}

The cascade has three tiers, as shown in Figure~\ref{fig:abc-cascade}. Each of the first two tiers has up to three voters, and the final tier has a single model, described below. A voter emits, per input chunk, either no output or one typed \texttt{AuditableSummary} object, which is a summary holding atomic findings described in Subsection~\ref{subsec:knowledge-map}, together with the metadata information needed to inspect the voter's extraction result. The best voter subset is selected during cascade calibration (§\ref{section:results-abc-calibration}): the production cascade has all three Level-1 voters, but drops one Level-2 voter, giving five voters across the two lower tiers that govern the voting decision, plus the single Level-3 fallback model (six models in total).

    \label{fig:abc-cascade}

\begin{itemize}[label={}, leftmargin=1.5em, itemsep=0.4em]
    \item \textbf{Level 1 -- Cheap voters.} The first level consists of cheap models that run in parallel on every input chunk. The voter pool includes models from different providers (OpenAI and Google) and model families. When models agree at this level, it indicates genuine consensus across distinct model families.
    
    \item \textbf{Level 2 -- Mid-tier voters.} When the L1 agreement score is not sufficient for acceptance, a second pool of moderately stronger models is invoked. The Level-2 candidate pool includes an Anthropic model, but the optimal voter-subset selection in Section~\ref{section:results-abc-calibration} excludes it; therefore, as with L1, the shipped L2 includes only Google and OpenAI models, so Anthropic enters the picture only at the last level, L3. At L2, the knowledge extraction is retried using a different, stronger set of models, rather than replaying it with the same cheap voters at L1. 
    
    \item \textbf{Level 3 -- Single strong model.} When L2 models also cannot agree on an output, the chunk escalates to the third and last level. The agreement scorer and thresholds apply only in the first two tiers; Level 3 includes the strongest language model in the cascade, and is an unconditional accept.
\end{itemize}

The exact voter models, their configurations, and the production voter profiles are listed in the appendix configuration table. This section focuses on the architecture, rather than the concrete model names. There are two important architectural decisions: first, voter diversity comes from using models from different providers, not from sampling variation; every production voter runs at temperature zero; second, the objects compared across voters are the typed MAP-stage outputs from Subsection~\ref{subsec:knowledge-map}. Agreement, therefore, is computed over structured extraction results, not raw free-text summaries.
