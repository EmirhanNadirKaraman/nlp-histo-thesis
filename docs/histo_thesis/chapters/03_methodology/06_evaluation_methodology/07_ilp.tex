\subsection{Selection of calibration dataset with integer linear programming}\label{subsec:eval-ilp}

Calibration and in-sample evaluation of the agreement-based cascading system and strict F1-score calculation of the knowledge-extraction pipeline, listed in Table~\ref{tab:research-questions} as RQ2 and RQ3, are done on a fixed 15-paper cluster, rather than the full 977-paper ingested corpus. The cluster has to satisfy three criteria: it should be small to keep the costs of silver-labeling with a strong LLM feasible; entity-rich to contain extractable biomedical claims; mutually related, so that the selected papers are likely to make claims about the same diseases, subjects and biomarkers, instead of completely unrelated claims, so that the cross-paper relation analysis (Subsection~\ref{subsec:knowledge-relate}) has signal. A random sample would not satisfy these criteria reliably, while a hand-picked set of papers would be subjective. Therefore, this selection is formulated as a constraint optimization problem, and solved with integer linear programming (ILP).

An offline, deterministic fingerprint is generated from each paper. The fingerprint contains \texttt{disease}, \texttt{biomarker}, \texttt{method}, \texttt{outcome}, \texttt{gene}, \texttt{tissue}, generic-entity, and UMLS-CUI buckets, collected from scispacy/UMLS named entity recognition \parencite{neumann2019scispacy, bodenreider2004umls}, regular expression logic, and a curated keyword dictionary. The relatedness score of a paper pair is computed as a weighted sum of Jaccard overlaps between entity buckets: disease overlap is weighted most heavily, while generic-entity overlap is down-weighted so that broad overlapping terms cannot dominate; a penalty is applied for papers that do not have any disease overlap, based on our assumption that papers about different diseases are less comparable, even if they share other features.

Some eligibility filters were used to keep the program tractable: only the papers that contain a number of sentences within the range 20--350, contain at least one non-empty disease, biomarker or gene entity bucket, and additionally, at least three distinct non-empty entities in total, were regarded as eligible. Afterwards, to make the graph more sparse, only the most related neighbors of each paper were kept, and the edges with a similarity score that is under a certain threshold were dropped. The model is implemented with PuLP, and solved with the CBC branch-and-cut solver~\parencite{mitchell2011pulp,forrest2019cbc}.

There are two tunable controls in the ILP paper selection procedure: the candidate cap, and a solver time budget. The candidate cap is applied through a pre-score calculated per paper: the number of disease, biomarker, and gene entities, divided by a logarithmic length term, which favors short, entity-dense papers. Papers are ranked by this score, and a number of papers are kept, to run the algorithm on the filtered subset of papers. The same pre-score supplies the fallback, which is used in case it is not possible to have $k$ papers in the output. 

Both controls can be relaxed or removed. When the candidate cap is removed, the ILP runs over the full eligible pool. The initial eligibility filters drop 56 papers, reducing the number of papers in the eligible pool from 977 to 921. When the time budget is also lifted, the program runs for longer, but is guaranteed to return an optimal solution.

Run with $k=15$, no candidate cap and no time limit, the relatedness ILP returns the cluster of papers used for in-sample knowledge-extraction and cascade evaluations. The selected papers are tightly interrelated: they are short, entity-rich papers with all $105$ pairs having a relatedness score $>0$. This cluster is the source of the knowledge-extraction's calibration silver labels, described in Subsection~\ref{subsec:eval-datasets}.
