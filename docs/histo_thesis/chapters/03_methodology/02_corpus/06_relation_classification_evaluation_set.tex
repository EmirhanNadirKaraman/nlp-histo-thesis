\subsection{Relation classification evaluation set}\label{subsec:relation-classification-eval-set}

The relation classification component uses the NLI classifier in the knowledge-extraction pipeline to label claim pairs with \texttt{SUPPORT} / \texttt{CONTRADICT} / \texttt{UNRELATED} tags. This component is evaluated on a separate set of 300 labeled claim pairs rather than relying on RELATE's outputs over the corpus. Since the rules generated over the corpus do not have ground-truth relation labels, the relation outputs can only be compared and analyzed indirectly, through relation counts and label stability across different configurations of the component, as described in Subsection~\ref{subsec:eval-grounding-and-relation-classification}. Therefore, to measure relation-classification directly, a labeled dataset is required.

300 claim pairs are generated by Opus 4.7 across a range of histopathology topics. Each claim pair is generated from an intended relation label, which serves as its silver reference; the relation classifier's output is then scored against it. The dataset is built independently of the ingested corpus, calibration, and other evaluation datasets, and is not sampled from pipeline-extracted rules.

No threshold or hyperparameter is tuned on the claim-pair dataset, so it provides out-of-sample measurements of the relation classifier; the full knowledge-extraction pipeline is evaluated separately (§§\ref{subsec:knowledge-extraction-eval-set} and~\ref{subsec:eval-knowledge-extraction}).

Since the claim pairs are synthetically constructed, the relations between them might be cleaner than the claim pairs in the corpus: a claim pair with a contradicting label might have a very obvious contradiction, supporting claims might be too similar, and unrelated claim pairs might be more plainly unrelated. Therefore, the accuracy metrics achieved on this synthetic dataset might overstate performance, compared to when running the relation classification on the corpus. This limitation is discussed in Section~\ref{section:disc-nli-as-shared-backbone}.
