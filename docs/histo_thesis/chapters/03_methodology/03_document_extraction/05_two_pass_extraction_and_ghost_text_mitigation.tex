\subsection{Two-pass extraction and ghost text mitigation}\label{subsec:doc-two-pass}

A class of PDF artifacts that Docling cannot catch on its own is what we call ``ghost text'': text objects that the parser detects as paragraphs but are not actually visible on the rendered page. Examples of these text artifacts include invisible-text layers used for accessibility and by typesetters for indexing. If these texts reported by the parser are not filtered out, they corrupt the extracted text passed down to later stages and can also distort the page header and footer boundaries. This is problematic because the pipeline uses these boundaries to separate real body text from the artifacts located in these regions. 

The pipeline uses a two-pass extraction procedure. The first pass identifies visible and invisible text, as well as non-body page regions such as headers and footers. The second pass re-runs structural parsing on a cleaned version of the PDF; its output is used by later stages, rather than Docling's raw output. 

In the first pass, Docling extracts the page layout, and each text element is checked against the rendered page. PyMuPDF renders the bounding boxes of each detected element to pixels. If an element contains text but the rendered region is visually blank, the Docling text element is rejected. In addition to this pixel test, there are two secondary tests. First, a density check rejects elements that contain an improbable number of characters in a very small vertical region; second, a color test flags white-on-white text. The second test, however, is disabled by default, as it risks removing legitimate white text on colored backgrounds.

The elements that survive scoring are the real, visible text of the page. From these elements, the extractor finds the top-most paragraph on each page and treats everything above it as the page header. Similarly, anything below the bottom-most paragraph is treated as the page footer, and blocks in the page margins are treated as sidebars. The header, footer, and sidebar bands, figures, tables, captions, and individual rejected text elements are all redacted from the PDF. Redaction removes the underlying text elements from the page rather than merely drawing a white rectangle on top, which would leave the underlying text extractable and thus recoverable by the second pass.

The second pass runs Docling again on the redacted PDF. This pass returns primarily legitimate body text and headings, which is what the text assembly stage (§\ref{subsec:doc-text-assembly}) consumes. Re-extraction, rather than deleting the rejected elements from the first-pass Docling output, allows Docling to re-segment the clean page into cleaner paragraphs. 

Two-pass extraction is the production default. Its purpose is not to handle figures or tables, but to clean up the body text passed downstream. 

The visibility tests are heuristic and deliberately conservative to ensure that legitimate text is not removed by mistake. The pipeline accepts this risk, rather than trusting Docling's text output unconditionally.
