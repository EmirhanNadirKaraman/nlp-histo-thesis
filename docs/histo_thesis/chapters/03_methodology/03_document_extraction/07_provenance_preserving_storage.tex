\subsection{Provenance preserving storage}\label{subsec:doc-provenance-preserving-storage}

The pipeline persists its output in both database and file representations. For each paper, a relational database stores one document row, keyed by its PMC identifier, together with text elements, figures, tables, and cross-references that link text elements to the figures and tables they cite. Each text element stores the source document identifier, its section path, and its position within the section, so that the original document sequence can be reconstructed in the correct order. Alongside the database records, the figure and table crops, the assembled hierarchical text, and a manifest file for the media a paper contains, are written to disk for each paper. 

Persistence with stable IDs, instead of treating extraction as a one-shot preprocessing step, is important for two reasons. First, the knowledge-extraction pipeline references these stable identifiers in every \textit{Finding}'s evidence field, and in every \textit{CanonicalRule}'s representative pointer. If the elements were re-extracted in memory on each run rather than persisted with stable IDs, the provenance chain that traces a final scored rule back to its source evidence would not survive from one run to the next. Second, the rubric-scored evaluation of Section~\ref{section:Evaluation_Methodology} runs offline against the persisted media manifest files and cropped images, allowing extraction quality to be scored repeatedly without re-processing the original papers each time. 

The provenance chain preserves traceability, but does not prove clinical validity or correctness: it lets the reader trace a final scored rule back to the paragraph it was inferred from, but it does not guarantee that the paragraph was interpreted correctly or that the inference itself is valid. The clinical validity and correctness of the entire system are bounded by the results in Chapter~\ref{chapter:Results}.

Each Docling pass and downstream stage caches its output. The Docling layout is keyed by the source PDF, and downstream outputs are keyed by configuration hashes, so papers are not reprocessed unless the configuration changes. This allows the corpus to be regenerated at near-zero compute cost with byte-identical results (Subsection~\ref{subsec:doc-extraction-purpose}).
