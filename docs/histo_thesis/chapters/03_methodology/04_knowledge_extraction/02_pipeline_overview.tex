\subsection{Pipeline overview}\label{subsec:knowledge-pipeline-overview}

The pipeline consists of seven stages, each of which consumes the typed object produced by the previous stage. The flow is mostly linear, except at the end: the RELATE stage computes the pairwise relations of the canonical rules, making RESOLVE the only stage that consumes two inputs --- the canonical rules from CANONICALIZE and the relations from RELATE, which it uses to score each rule. Figure~\ref{fig:ke-pipeline} shows these stages with their per-stage input and output types. 

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\textwidth]{figures/03_methodology/04_knowledge_extraction/01_knowledge_pipeline.pdf}
    \caption[Knowledge-extraction pipeline.]{Knowledge-extraction pipeline, with each arrow labeled by the typed object it emits. GROUNDING is a filter, so it preserves the type; RESOLVE takes two inputs.}
    \label{fig:ke-pipeline}
\end{figure}

The input is the paragraph-level text from document extraction, segmented into sentence chunks, each tagged with a stable database identifier of the paragraph it was segmented from. The output is a list of \texttt{FinalRule} records, which are typed, ranked, and traceable back to their source texts; and a separate list of \texttt{Relation} records, which describe the links between the rules.

MAP is the only stage that calls a large language model; it converts input chunks to typed candidate findings. Every other stage is deterministic. GROUNDING and RELATE share a single cross-encoder NLI model: GROUNDING discards findings whose verbatim support does not entail the claim, while RELATE classifies the relationship between canonical rules. NORMALIZE resolves entities using a fixed UMLS-supported linker, GROUP clusters compatible findings, CANONICALIZE converts grouped findings into rule candidates, and RESOLVE assigns the final rule scores. Confining the stochastic part of the system to a single MAP stage makes the cost-quality calibration of MAP, described in Section~\ref{section:Agreement_Based_Cascading}, a self-contained engineering problem.
