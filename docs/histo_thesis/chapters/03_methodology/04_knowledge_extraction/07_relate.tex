\subsection{RELATE: pairwise rule relation classification}\label{subsec:knowledge-relate}

The RELATE stage takes pairs of canonical rules and classifies the relation between them. It runs first within a single paper, and then across papers in a corpus-level pass, described at the end of this subsection. The three relation labels used in the RELATE stage are as follows: 

\begin{itemize}[label={}, leftmargin=1.5em, itemsep=0.4em]

    \item \textbf{SUPPORT.} Two rules are labeled as supporting when they entail each other in both directions.
    
    \item \textbf{CONTRADICT.} Two rules are labeled as contradicting when they share the same subject-outcome-relation triple, disagree on polarity, and NLI comparisons in both directions exceed the contradiction threshold. Same-polarity claims suppress the contradiction labeling because the system treats pairs with the same polarity as co-observations rather than disagreements. 
    
    \item \textbf{UNRELATED.} A pair is labeled as unrelated, either when it fails the comparability gate and never reaches the NLI model, or when it reaches the NLI model but does not exceed the entailment or contradiction thresholds.
    
\end{itemize}

In order to reduce processing time, a comparability gate filters pairs of canonical rules, checks if both rules in the pair have polarity-bearing directions (a pair involving an \texttt{unclear} or \texttt{no\_direction} rule is skipped), and have the same subject entity, outcome entity, category, and relation type. Entity compatibility is based on UMLS CUIs first, and normalized string matching as a fallback. The gate keeps processing time manageable by restricting the NLI classifier to \texttt{CanonicalRule} pairs that may plausibly support or contradict each other.

After the comparability gate, RELATE converts each \texttt{CanonicalRule} into text before the NLI model scores it. There are two independent choices for that text. The first decision is to use either the abstracted, short predicate text, such as ``CD30 is expressed'', or the full source paragraph behind the representative member of the \texttt{CanonicalRule}. The second decision is whether or not to prepend a compact scope tag, such as \texttt{[scope: disease=ALCL]}, to the rule. The two axes give four input modes; production uses the abstracted predicate with the scope tag. The choice is not cosmetic: two rules can look identical to the model, even though they address different diseases; so the input mode can change the SUPPORT, CONTRADICT, or UNRELATED label a pair receives.  Section~\ref{section:results-nli-in-grounding-and-relation-classification} reports how many relations each mode produces and how stable the labels are across different modes; Chapter~\ref{chapter:Discussion} interprets those differences. 

A corpus-level pass produces cross-paper relations by applying the same comparability gate and NLI classifier to \texttt{CanonicalRule} pairs from different papers, rather than a single one. This pass is where agreement or contradiction between different papers can surface. At this scale, the comparability gate is essential: the number of candidate pairs grows quadratically with the size of the rule base, and restricting the NLI to gate-passing pairs is what keeps the corpus-level pass tractable. In practice, the corpus yields few such relations, as shown in Section~\ref{section:results-ke-pipeline-output-and-provenance}; this sparsity and its effect on evaluation are discussed as limitations in future work.
