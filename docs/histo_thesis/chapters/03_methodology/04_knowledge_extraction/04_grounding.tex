\subsection{GROUNDING: NLI-based support filtering}\label{subsec:knowledge-grounding}

The GROUNDING stage filters each MAP finding by checking if the cited text actually entails the claim. This cited text is the original source paragraph that was substituted during MAP post-processing (§\ref{subsec:knowledge-map}), not the LLM-generated paraphrase. a biomedical NLI cross-encoder, \texttt{pritamdeka/PubMedBERT-MNLI-MedNLI}~\parencite{deka2023pubmedbertextended}, which has PubMedBERT as its base and is fine-tuned on MNLI and MedNLI datasets~\parencite{gu2021biomedbert, williams2018mnli, romanov2018mednli}, is used to determine whether the source text entails the claim: the model outputs an entailment score between 0 and 1, and findings whose entailment score is below a certain threshold are dropped. 

GROUNDING is a supporting filter, not a correctness check: it removes findings with claims that appear not to be supported by their evidence, but a surviving claim is not guaranteed to be scientifically correct -- the output is never verified by a domain expert. 

The same NLI model is reused in the RELATE stage (§\ref{subsec:knowledge-relate}). In GROUNDING, it scores a source paragraph against an extracted claim; in RELATE, it scores one rule against another. The two stages use the shared NLI backbone differently: GROUNDING applies a single entailment threshold to decide whether a finding should be kept or discarded, whereas RELATE applies separate entailment and contradiction thresholds to classify each canonical rule pair as \texttt{SUPPORT}, \texttt{CONTRADICT}, or \texttt{UNRELATED}. The empirical behavior of the shared backbone is reported in Section~\ref{section:results-nli-in-grounding-and-relation-classification}, and the results are discussed in Section~\ref{section:disc-nli-as-shared-backbone}.
