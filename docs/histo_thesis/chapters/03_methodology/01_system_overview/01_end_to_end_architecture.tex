\subsection{End-to-end architecture}\label{subsec:end-to-end-architecture}

The system filters and downloads histopathology papers from the PubMed Central Open Access Subset, parses them into a structured format suitable for a relational database, and produces scored biomedical rules whose fields can be traced back to their sources. The end-to-end flow consists of four stages, shown in Figure~\ref{fig:system-architecture}.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\textwidth]{figures/03_methodology/01_system_overview/01_system_architecture.pdf}
    \caption{End-to-end system architecture.}
    \label{fig:system-architecture}
\end{figure}

\begin{enumerate} 

    \item \textbf{Paper selection and filtering.} Papers are selected by keyword filtering (e.g., histopathology, histology, immunohistochemistry, H\&E, biopsy, whole-slide image) in the article title/citation, while excluding other imaging modalities (MRI, CT, ultrasound) and non-human studies (mouse, rat, veterinary). These keywords were suggested by an LLM. The selected papers are then downloaded; all downloaded papers are available in both PDF and JATS-XML formats, but only the PDF files were used, since the pipeline is designed not to depend on XML representations, which are not consistently available across the scientific literature (§\ref{subsec:doc-input-sources}). 
    
    \item \textbf{Document extraction pipeline.} Each of the downloaded papers is parsed by a PDF document extraction pipeline. A Docling-backed hybrid table detector and a two-pass invisible-text guard are used to improve text extraction quality. The resulting output is a set of provenance-preserving document elements (text, figures, tables, captions, and cross-references). These results are written into a PostgreSQL relational database.
    
    \item \textbf{Knowledge extraction pipeline.} The document elements are consumed by a knowledge extraction pipeline, which decomposes texts into atomic findings, filters them through an NLI grounding gate, normalizes and groups them, produces canonical rule candidates, classifies pairwise relations between rules, and scores final rules. 
    
    The first stage of the knowledge extraction pipeline, MAP, is the core of the pipeline: a three-tier agreement-based cascade system calculates per-chunk agreement scores to decide whether to escalate to a higher tier with better, more expensive models, accept the cheap-tier output, or reject the chunk output altogether.
    
    \item \textbf{Final outputs and evaluation.} The system emits scored rules with full provenance, where the source evidence for each rule can be tracked and retrieved from the database. The experiments and evaluation scripts read the persisted artifacts offline (§\ref{subsec:overview-reproducibility-and-artifact-design}) to measure and report the behavior of each subsystem. 

\end{enumerate}
